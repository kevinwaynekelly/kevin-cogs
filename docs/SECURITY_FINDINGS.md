# Security findings assessment

Reviewed October 4, 2026. The reported scan inspected [`2f2a6d4`](https://github.com/kevinwaynekelly/kevin-cogs/commit/2f2a6d4f71ff928fa5d27d8ecf9859d590bbd6d0). The first validated hardening checkpoint is on main at [`11baf67`](https://github.com/kevinwaynekelly/kevin-cogs/commit/11baf67161308bd5c673530df4f29281bb81ef11). This is a code assessment, not confirmation that the scanner has rerun or closed its findings.

| Severity | Finding | Assessment and action |
| --- | --- | --- |
| High | Unrestricted template format widths can exhaust the shared bot | Hardened LevelPlus formatting before expansion: bounded width, precision, specifications and output; nested fields and traversal rejected; unsafe saved templates fall back safely. CommunityPlus welcome and goodbye templates use equivalent bounded formatting with safe legacy fallbacks. |
| Medium | XP CSV exports preserve spreadsheet formulas in member-controlled aliases | Hardened. Formula-like cells are exported as literal text, including prefixes hidden behind whitespace or control characters. Stored aliases stay unchanged. |
| Medium | Emergency administrator recovery creates a hijackable, self-assignable role | Hardened. Recovery stages a new unprivileged role, checks fresh hierarchy and complete member enumeration, assigns only the invoking bot owner, rechecks ownership, then grants Administrator. It requires the Members intent, a known member count no greater than 100,000 and complete listing within 30 seconds. Unsafe hierarchy, other role holders or incomplete recovery abort and clean up the staged role. Existing roles require manual review, described below. |
| Medium | Unbounded activity telemetry permits persistent Config growth | Accepted behavior. The owner explicitly wants lifetime member/activity history preserved without automatic pruning. Daily counters remain bounded; lifetime member records and game catalogs can grow. `community tracking false` stops collection, privacy deletion removes the requested user's records, and settings-only exports keep telemetry out of configuration repositories. |
| Medium | Audio lookups can accumulate an unbounded pending task backlog | Hardened. Admission rejects overload before lookup or voice work enters a waiting queue, with both global and per-server request limits. Accepted tasks remain owned and are cancelled on unload. |
| Medium | In-flight AudioPlus commands can recreate user data after deletion returns | Hardened. A deletion barrier associates pending operations with their affected users, cancels old operations, waits for their cleanup, and serializes persistent writes before erasure. It does not retain permanent user tombstones. |
| Medium | One user-data deletion request erases every administrator's ExportPlus job | Hardened. Only exports requested by that user or containing their authored rows are erased. Unaffected active scans omit later rows by the deleted author; affected scans and downloads are cancelled. Unrelated archives remain intact. |
| Medium | LogPlus exposes retained private-channel events without source-channel authorization | Hardened. Current requester and bot visibility/history permissions are required before limits, counts, search, export or incident display. Private threads also check current membership or Manage Threads access. Deleted or unavailable sources and incident copies with unknown provenance stay hidden. |
| Medium | Display names can inject mentions into configured level-up notifications | Hardened. Display-name mentions are escaped and allowed mentions restrict notifications to the leveling member. Role, everyone, here, reply and other-member mentions are suppressed in both live notices and previews. |
| Medium | Member-supplied media URLs permit requests to private networks | Hardened. AudioPlus and IntroPlus use a public-destination dial guard for extraction and a guarded streaming relay for FFmpeg. Private, loopback, reserved, metadata and mixed public/private DNS destinations are rejected at transport boundaries. Redirects are checked; proxy environments and HLS/DASH manifests are unsupported. Supported media paths passed controlled network and real local FFmpeg regression checks; live YouTube access remains unverified. |
| Medium | Automatic OwoPlus reposts download attachments without a byte or concurrency budget | Hardened. Reposts reserve bounded global/per-server work before downloads, enforce metadata and streamed-byte budgets and timeouts, and allow only Discord attachment CDN URLs without redirects. Failure leaves the original message intact. |
| Low | One guild can starve every other guild's automatic emoji capture queue | Hardened. Automatic capture uses per-server pending limits and round-robin server scheduling inside a bounded shared queue. |
| Low | User-data export can omit a retained daily earned-XP record | Hardened. User-data exports include the earned-XP total and its local date even when no other XP or alias record exists. Deletion clears the same retained record. |
| Low | Default automatic emoji capture lets ordinary members consume server expression slots | Accepted behavior. Normal-member capture is the requested feature and stays enabled by default. Administrators can disable capture or restrict its channels. Existing server emojis are never deleted to make space; slot checks, deduplication and queue/download limits still apply. |
| Low | Member lookup leaks cached user identities across guild boundaries | Hardened LevelPlus lookup to use current server members and explicitly retained aliases for that server, rather than the bot-wide user cache. CommunityPlus already uses server-scoped members and did not need a lookup change. |
| Low | AudioPlus setup guidance executes an unpinned remote installer as root | Hardened. Setup now uses a fixed official release archive over HTTPS and verifies its pinned, reviewed SHA-256 before extraction or installation. It no longer pipes an unversioned downloaded installer into a root shell. |

## Existing recovery roles

New recovery code never adopts a role merely because its name is `Restored Admin` or resembles the new role name. Older releases did not retain trustworthy role-origin metadata, so automatic deletion or modification could affect a legitimate administrator role. Review existing recovery roles in Discord, remove unintended holders, and delete or reposition any role that ordinary role managers can assign. The code changes do not retroactively repair roles already created on a live server.

## Verification and scope

All **1,235 tests passed on Python 3.10 and Python 3.11**. Ruff lint/format checks, dashboard frontend syntax/interaction checks, pinned-installer shell syntax and `git diff --check` also passed. Regression tests exercise the real Red command pipeline and Config, filesystem and serialization behavior. Discord voice/history/role APIs and external media providers are mocked or represented by controlled local fixtures. They do not establish that the updated cogs are deployed to Scarlet, that Discord's live permissions behave identically during concurrent external changes, or that YouTube playback succeeds from the Red container.

CommunityPlus template/recovery checks passed on both supported Python versions, including fresh staged-role holder verification through the mocked REST boundary. Media regressions check actual guarded HTTP/FFmpeg behavior with local fixtures and explicit test-only loopback allowances; production has no loopback/private-network exception. Audio deletion regressions include cancellation-resistant old operations, interrupted overlapping erasure and pending session-summary delivery. Rerun the security scan against the final main commit to confirm findings independently; no remote finding status has been changed by this document. The two explicitly accepted feature behaviors remain documented rather than silently removed.

## Apply the update

On Scarlet, run `!cog update True` as the bot owner to update and reload installed cogs. Both AudioPlus and IntroPlus need the guarded media helpers from this revision. No Config migration or new slash-command sync is required for these changes. Run `!audiostatus`, test a public song, and review any old recovery role's holders and hierarchy in Discord. If the container has HTTP/HTTPS/ALL proxy variables, remove them and restart Red; native music/intros now reject that routing.
